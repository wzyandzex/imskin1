# IMSkin 总规划与开发基线

> 版本：v1.0
> 状态：开发基线（2026-08-15）
> 适用范围：当前工作区及后续所有功能、修复、适配和发布工作
>
> 本文是后续开发的总入口。产品“做什么”由本文件与《需求规格说明书.md》共同定义；数据和边界以 `docs/01-领域模型与数据契约.md` 为准；平台事实以 `docs/02-平台能力矩阵与适配契约.md` 为准；质量和发布以 `docs/03-质量门禁与验收协议.md` 为准。

## 1. 先给结论

当前项目是一个**输入法皮肤生成与真实交互预览工作台原型/MVP**，不是已经完成四端真机交付的生产服务。

已有能力的工程状态与用户可交付状态必须分开描述：

- 源码已实现，不代表用户体验已验收。
- 测试通过，不代表真实客户端接受包。
- ZIP/INI/XML 结构正确，不代表可以安装。
- Web 中有资源，不代表导出包包含同样资源。
- 界面有平台标签，不代表预览已经加载平台差异。

后续所有界面、CLI、API 和文档必须使用下面的出口交付等级：

| 等级 | 标识 | 含义 | 对用户可说的话 |
|---|---|---|---|
| 结构可生成 | `structural` | 容器、编码、必需结构和引用可由程序验证 | “已生成实验包结构” |
| 可预览 | `previewable` | 目标资源/能力已接入 Web 预览并通过真实浏览器交互测试 | “可在工作台预览” |
| 待安装验证 | `install_candidate` | 资产、QA、包级检查均通过，可交给指定客户端安装 | “待指定版本客户端验证” |
| 真机已验证 | `install_verified` | 指定客户端/设备安装、显示、重启和关键交互回归通过 | “可安装包” |
| 阻塞 | `blocked` | 存在已知阻断或外部验证失败 | “暂不可交付，见卡点” |

只有 `install_verified` 可以在面向普通用户的界面显示“可安装包”。开发者可以用明确的实验开关生成较低等级的产物，但不得伪装成正式包。

## 2. 产品方向和首发策略

### 2.1 产品定位

用户用文字想法或参考素材生成输入法皮肤，在 Web 中像真实输入法一样试打，通过自然语言和元素标注进行局部迭代，保留版本树，最后在用户明确确认后导出目标平台包。

核心价值不是生成一张键盘效果图，而是：

```text
模糊意图
→ 可确认的 Design Brief
→ 可交互的输入法预览
→ 可解释的局部反馈
→ 可回退的版本树
→ 有质量证据的目标出口
```

### 2.2 用户优先级

1. **首发用户：普通创作者**。不熟悉设计软件，希望快速做出可用的个性化输入法皮肤。
2. **第二用户：有明确审美想法的用户/设计师**。重视参考素材还原、局部精修和版本对比。
3. **内部角色：运营/兜底人员**。处理适配、真机和外部工具失败，不作为当前公开工作台的主用户。

首发主流程是：

```text
文字/参考素材
→ Brief 展示与确认
→ 设计生成
→ 平台×设备预览
→ 真实试打
→ 自然语言反馈
→ 版本 Fork/比较
→ 用户确认此版本
→ 逐出口 QA/导出
```

### 2.3 出口策略

目标仍然覆盖：

- 搜狗 PC（`.ssf`）
- 搜狗 Android（`.ssf`）
- 百度 PC（`.bps`）
- 百度 Android（`.bds`）

但四个出口独立推进、独立报告状态、独立失败和重试。四出口是战略范围，不意味着必须同时达到 `install_verified`。

推荐第一个黄金出口为**搜狗 PC**，理由是现有实现路径最直接、移动真机碎片化较少、适合先建立“生成→资源→导出→安装→回归”的完整证据链。移动预览仍与黄金出口并行开发，不得因为先做 PC 而退化为静态图或伪交互。

### 2.4 明确不属于当前发布阻塞

以下能力保留方向，但不阻塞第一条黄金出口：

- 照片一键成皮和完整图像生成；
- 模板/IP 授权库；
- 公开分享链接、账号和云端多租户；
- MCP；
- 跨项目偏好学习；
- 社区/商店分发。

它们必须在进入开发时另建 PRD/ADR，不得仅因为界面有入口就宣称完成。

LLM、图像模型、REST/CLI/SDK 是可选的本地/自托管扩展。确定性路径在没有模型时仍可运行；一旦连接外部模型，必须遵守密钥、网络、超时、大小和降级规范。

“移动端”在正式文件中统一指 Android；iOS 不提供外部可导入皮肤包，只能提供预览或设计稿边界说明。

## 3. 不可妥协的产品原则

### 3.1 真实体验优先

不接受以下替代品冒充核心能力：

- 静态效果图冒充皮肤；
- 录屏或截图轮播冒充输入；
- 一套通用平台逻辑只换文件名；
- 写死候选词冒充真实拼音/T9；
- 非空 ZIP 冒充可安装包；
- 只展示“已学习偏好”但不影响生成；
- 透明点选层遮住真实输入后仍称为“可交互预览”。

### 3.2 诚实表达不确定性

每个外部事实、实现能力和发布资格都必须有状态。不能把“逆向样本确认”“结构测试通过”“浏览器模拟”和“真机安装通过”写成同一件事。

### 3.3 局部反馈必须可解释

反馈处理前生成结构化目标和变更指令。系统应能告诉用户：

- 识别到了哪个元素；
- 修改了哪个字段；
- 哪些元素受到保护；
- 哪个出口被重跑；
- 是否因为平台差异产生受控变化。

低置信度不能静默生成一个看似成功的新版本，应先请求用户确认目标。

## 4. 目标架构边界

暂不拆微服务，保留当前 npm workspaces 和零依赖核心包，但补出稳定契约。

```text
contracts（跨包类型、schema、出口和状态）
  ↓
pinyin-engine / skin-gen / project-model / feedback-core / qa-core / adapters
  ↓
orchestrator（编排、重跑、状态、provenance）
  ↓
api / web-app（边界适配，不承载领域真相）
```

推荐后续新增 `packages/contracts`，逐步承接跨包公共类型。现有包先兼容导出，避免一次性重写。

### 4.1 设计层

负责 Idea、DesignBrief、VisualSpec、颜色/字体/圆角/动效意图和用户确认。不得依赖 `.ssf/.bps/.bds` 的私有字段。

### 4.2 资产层

负责 AssetBundle、资源用途、`element_id`、尺寸、DPI、状态、九宫格安全区、帧、音效、触感引用、hash、来源和 QA 状态。资产必须进入版本快照，不能只在导出时以裸 `images[]` 临时传入。

### 4.3 目标变体层

设计层之下建立四个 `TargetVariant`：

```text
sogou_pc
sogou_android
baidu_pc
baidu_android
```

每个目标拥有独立能力矩阵、资产集、预览 profile、适配状态、QA 报告和 PackageArtifact。平台反馈只更新对应目标，通用风格反馈才同步所有目标。

### 4.4 适配器层

四个适配器继续隔离格式细节，但对外逐步统一：

```text
capabilities(target)
build(targetVariant)
validateArtifact(artifact)
previewProfile(target)
installVerificationProfile(target)
```

适配器内部可以继续使用各自的 INI/XML/ZIP 模型，不能让这些格式泄漏到设计层或预览域。

## 5. 两条正交状态轴

### 5.1 版本生命周期

```text
draft
  → brief_pending_confirmation
  → generating
  → ready
  → confirmed
  → exporting
  → completed

任一阶段可进入 blocked/failed；fork 后新版本回到 draft。
```

现有 `VersionStatus` 需要兼容迁移；`exported` 不再代表真机验证，只能作为历史状态读取。

### 5.2 出口交付状态

```text
not_started → queued → generating → qa → install_candidate → install_verified
                                      ↘ failed（附 stage/retryable/diagnostics）
```

两个状态轴不能合并。一个版本可以已经 `confirmed`，但四个目标分别处于不同交付等级。

## 6. 质量发布原则

质量检查按以下顺序执行：

```text
Schema/契约
→ 资产完整性
→ 渲染后可读性和遮挡
→ 适配器包结构
→ 跨出口一致性
→ 浏览器真实交互
→ 指定客户端/真机安装
→ 性能、安全和人工签收
```

硬阻断：未确认版本、必需资源缺失、引用不闭合、QA error、包结构失败、适配器失败、真机验证失败。

warning 可以继续，但必须在导出卡片中显示并记录。没有真机证据时最高只能是 `install_candidate`。

初始质量预算：

- 关键普通文字对比度默认 `>= 4.5`；自动修复一次，仍失败则阻断。
- 图片/复杂渐变必须基于实际渲染后的多位置采样，不能只返回“待检查 warning”。
- 资产引用闭合率 100%。
- 性能使用固定环境和 P95：按键→候选 `<=50ms`、音效触发 `<=30ms`、版本切换 `<=1s`、动效目标 `>=50fps`。
- 一致性阈值在黄金样本校准前不伪造精确数值；先使用 token 规则、固定 fixture 和人工签收。

## 7. 分阶段路线

### Phase 0：规范和事实收口

归档旧文档、创建本目录规范、统一状态词汇、建立证据模板、清理 SRS/架构/Handoff/README 冲突。没有完成前，不以“已完成四出口”作为发布结论。

### Phase 1：修复承诺与实际不一致

- `UX-001` 接通符号/数字/返回面板状态；
- `UX-002` 分离试打模式和标注反馈模式；
- `UX-003` 实现 Brief/定稿确认门禁；
- `UX-004` 补反馈 loading、异常、重试和重复提交保护；
- `UX-005` 修复窄屏反馈栏和关键无障碍；
- `PRE-001` 把目标 outlet/profile 传入预览并诚实显示差异。

### Phase 2：稳定领域契约、版本和任务

- `DOM-001` 建立 contracts；
- `DOM-002` typed snapshot、schema、深层不可变和迁移；
- `JOB-001` 四出口独立任务、阶段、进度、失败、重试、取消和 TTL；
- `PIPE-001` 目标象限定向重跑、结构化诊断和 provenance。

### Phase 3：资产、QA 与黄金出口

- `ASSET-001` AssetBundle/AssetProfile 和引用闭合；
- `QA-001` 分层 QA gate、图片采样、适配器和包级校验；
- `OUT-SGPC-001` 补齐搜狗 PC 资产和打包策略；
- `EVID-001` 产出搜狗 PC 真机安装证据；
- `PINYIN-001` 词库选择、覆盖率和延迟 benchmark。

### Phase 4：移动预览真实度

- `MOB-001` panel、符号/数字/表情、T9/26 键和候选横向翻页；
- `MOB-002` 长按、上滑、滑行（平台支持时）、音效、振动检测和诚实降级；
- `MOB-003` 真实 DPR 资源 profile 和发虚定位；
- `MOB-004` 两个 Android 目标的预览 profile。

### Phase 5：其余出口逐个真实验收

搜狗 Android、百度 PC、百度 Android 必须逐个走同样的格式、资产、QA、安装、重启和关键交互证据链。一个出口失败不能被总进度隐藏。

### Phase 6：安全、可靠性、工程门禁和观测

对外共享 API 前必须完成认证边界、SSRF 防护、secret 处理、job TTL/并发/错误码、统一 `test/typecheck/build/lint/ci`、结构化日志和指标。

### Phase 7：延后能力

模板/IP、公开分享、云端、多租户、MCP、跨项目偏好、协作和批量生产另立需求与 ADR。

## 8. 变更完成定义（Definition of Done）

任何任务只有同时满足以下条件才可写“完成”：

1. 代码实现；
2. 自动化测试；
3. 文档状态更新；
4. 失败/降级文案；
5. 相关观测字段；
6. 证据包或明确记录“外部证据阻塞”；
7. 可回滚方式；
8. 不引入新的未登记 provisional。

## 10. 当前已知事实和明确未知

### 已知

- 当前是 Node >=22 npm workspaces monorepo。
- `skin-gen`、`pinyin-engine`、`feedback-core`、`project-model`、`qa-core`、四个 adapter、orchestrator、api 和 web-app 均有源码与测试。
- 当前静态测试统计约 305 个，但统计脚本尚未统一；以未来 CI 输出为准。
- 四出口结构适配器已存在，字段/目录来自代码和逆向资料；真实客户端安装尚未形成证据。
- 默认导出可能没有真实位图、完整移动布局和完整平台资产。
- 平台预览、面板切换、定稿门禁、四出口独立进度存在实现缺口。

### 未知/不得假定

- 任一出口当前主流客户端一定接受生成包；
- 百度 PC 的当前压缩方式和百度 Android Token 语义已经最终确认；
- 种子词库能代表日常中文输入；
- 图片/渐变的静态 QA 能代表渲染后可读性；
- 当前浏览器模拟能代表真机音效、振动、DPI 和厂商行为；
- 前端 localStorage 保存 API Key 符合生产安全要求；
- 内存 job 能代表可靠异步队列。
