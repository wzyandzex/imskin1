> 关联：`docs/00-总规划与开发基线.md`、`docs/01-领域模型与数据契约.md`

## 1. 使用规则

本文是四个目标出口的平台事实和完成状态的唯一矩阵。代码注释、逆向笔记和旧 Handoff 可以作为证据输入，但不能单独覆盖本矩阵。

合法状态只有：

```text
not_started
structural
previewable
install_candidate
install_verified
blocked
```

状态解释见 `docs/00-总规划与开发基线.md`。状态升级必须引用 Evidence ID；没有 Evidence 时不得升级。

当前矩阵中的 `structural` 仅表示源码能够构造并由自动化测试解析结构，不表示真实客户端可安装。

## 3. 统一 PlatformAdapter 契约

目标接口：

```ts
interface PlatformAdapter<TProject> {
  readonly outlet: Outlet;
  readonly version: string;

  capabilities(): CapabilitySnapshot;
  assetProfile(): AssetProfile;
  previewProfile(): PreviewProfile;
  build(input: TargetVariant): BuildResult<TProject>;
  validateProject(project: TProject): ValidationReport;
  validateArtifact(bytes: Uint8Array): StructuralReport;
  installVerificationProfile(): InstallVerificationProfile;
}
```

### 3.1 BuildResult

```ts
interface BuildResult<TProject> {
  project: TProject;
  artifact: PackageArtifact;
  structuralReport: StructuralReport;
  diagnostics: Diagnostic[];
}
```

构建失败不返回假 Artifact。若允许实验包，`artifact.experimental=true` 且 deliveryLevel 不高于 `structural`。

### 3.2 CapabilitySnapshot

```ts
interface CapabilitySnapshot {
  outlet: Outlet;
  layouts: ("pc_qwerty" | "android_qwerty" | "android_t9")[];
  orientations: ("portrait" | "landscape")[];
  themes: ("light" | "dark" | "paired" | "system")[];
  densities: string[];
  candidateModes: string[];
  keyStates: string[];
  supportsSound: boolean;
  supportsAnimation: boolean;
  supportsHapticsIntent: boolean;
  supportsSwipeVisuals: boolean;
  provisional: string[];
}
```

“平台支持”必须来自版本化证据；未知时填 provisional，不能按产品愿望填 true。

## 5. 搜狗 PC

### 5.1 当前结构事实

代码位置：

- `packages/sogou-adapter/src/skin-ini.ts`
- `packages/sogou-adapter/src/ssf.ts`
- `packages/sogou-adapter/src/encrypt.ts`

当前实现能够：

- 生成 `skin.ini`；
- 以 UTF-16LE 写入；
- 打包 ZIP 并使用 `.ssf` 后缀；
- 写入部分 Display/Scheme/StatusBar 字段；
- 可附带图片；
- Node 专属路径支持实验性加密容器。

当前自动化证据证明：

- ZIP 可解析、CRC 可回读；
- `skin.ini` 可生成并包含测试字段；
- 编码路径在测试中按 UTF-16LE 验证。

### 5.2 未闭环事项

- 主流搜狗 PC 客户端是否接受当前明文 ZIP；
- 是否需要 BOM、加密容器或其他兼容标记；
- 完整字段字典、候选序号色、APNG 帧率等边缘字段；
- 真实窗口背景、状态栏和九宫格资产；
- 深浅主题的客户端携带方式；
- 安装、皮肤列表出现、重启后保留和真实显示。

### 5.3 PreviewProfile 目标

至少体现：

- 搜狗 PC 候选栏布局；
- 横/竖候选模式；
- 状态栏图标和中英文状态；
- 搜狗允许的候选、拼音、序号颜色；
- 不支持或未验证能力的明确标记。

当前 Web PreviewRuntime 未接收 outlet，故不能标记 `previewable`。

### 5.4 升级到 install_candidate

必须满足：

- 固定 `AssetProfile` 必需资源 100% 完整；
- `skin.ini` schema、编码、引用和 ZIP 路径校验通过；
- 浏览器基于搜狗 profile 完成规定交互；
- 关键文字、位图和九宫格 QA 通过；
- Artifact 生成 SHA-256 和 structural report。

### 5.5 升级到 install_verified

固定客户端版本和 Windows 版本，验证：

1. 双击或规定路径安装成功；
2. 出现在皮肤列表；
3. 候选窗、拼音串、状态栏显示；
4. 中英切换、候选翻页等关键状态显示；
5. 深浅/横竖模式按声明工作；
6. 客户端重启后仍可用；
7. Artifact SHA-256 与 evidence manifest 一致。

## 6. 搜狗 Android

### 6.1 当前结构事实

代码位置：

- `packages/sogou-mobile-adapter/src/ssf.ts`
- `packages/sogou-mobile-adapter/src/theme.ts`
- `packages/sogou-mobile-adapter/src/layout.ts`

当前实现能够构造：

```text
phoneTheme.ini
Skin.ini（兼容入口）
theme/<layout>/...
colors.ini
res/
resblack/
```

APK/逆向资料表明外层是普通 ZIP，但当前测试只证明结构可构造。

### 6.2 未闭环事项

- 当前主流客户端导入入口和接受规则；
- 精确布局 INI 键名、取值和大小写；
- 九宫格/26 键、功能栏、候选栏的真实模板；
- port/land 和 DPI 资源；
- `res/resblack` 的深浅切换规则；
- 音效、动效、手势资源支持范围；
- 真机导入、显示和重启回归。

### 6.3 PreviewProfile 目标

- 搜狗 Android 的九宫格、26 键和功能栏布局；
- 候选横向翻页；
- 符号/数字/表情面板；
- 长按/上滑副字符；
- 真机不等价能力提示；
- 基于真实 DPR 资源而不是纯 CSS 放大。

### 6.4 真机矩阵最低要求

- 一个当前主流搜狗 Android 版本；
- 至少一台物理 Android 设备；
- 首次验证至少覆盖 xxhdpi，随后扩展 mdpi/xxxhdpi；
- 竖屏必测，横屏在声明支持时必测；
- 九宫格和 26 键均需截图与操作记录。

## 7. 百度 PC

### 7.1 当前结构事实

代码位置：

- `packages/baidu-pc-adapter/src/bps.ts`
- `packages/baidu-pc-adapter/src/skin-ini.ts`
- `packages/baidu-pc-adapter/src/skin-xml.ts`
- `packages/baidu-pc-adapter/src/ui-xml.ts`

当前实现能够生成：

```text
skin.ini（UTF-16LE）
Skin.xml
Candidate.xml
Status.xml
位图资源（调用方提供）
```

代码当前使用 store ZIP；资料指向真实包通常为 deflate。这个差异是发布阻塞事实，不能仅凭标准 ZIP 可解压关闭。

### 7.2 未闭环事项

- 当前客户端是否接受 store ZIP，或必须 deflate；
- metadata、GUID、时间、版本字段规则；
- Candidate/Status XML 的真实坐标和控件覆盖；
- 安装器是否存在未记录校验；
- 真实位图和状态图；
- 安装、皮肤列表、重启和显示。

### 7.3 PreviewProfile 目标

- 百度 PC 候选窗和状态栏行为；
- 与搜狗不同的控件、功能和候选布局；
- normal/over/down 状态；
- 平台不支持能力的降级。

### 7.4 真机验证必须对照

至少构建 store 和 deflate 两个候选包，其他输入完全一致，记录客户端结果；验证后只保留证据支持的默认策略，另一条作为明确 fallback 或删除。

## 8. 百度 Android

### 8.1 当前结构事实

代码位置：

- `packages/baidu-mobile-adapter/src/bds.ts`
- `packages/baidu-mobile-adapter/src/info.ts`
- `packages/baidu-mobile-adapter/src/layout.ts`
- `packages/baidu-mobile-adapter/src/ini.ts`

当前实现能够生成：

```text
Info.txt
Token.txt
port/
land/
css.ini
可选 keyshape.json / preview / images
```

### 8.2 发布阻塞事项

- `Token.txt` 的 MD5 输入语义；
- 当前主流版本接受 `.bds` 还是其他后缀；
- 是否需要登录、联网或服务器登记；
- port/land、`.cnd/.pop` 和 css 的精确规则；
- keyshape/动画等高级能力的真实支持；
- DPI、音效、手势和功能栏能力；
- 真机导入和重启回归。

当前 `Info.txt` 字节 MD5 只能标记 provisional，不得进入 install_candidate。

### 8.3 Token 验证实验

实验必须使用相同资源和 Info，分别构造候选 Token：

- Info 原始字节 MD5；
- 除 Token 外所有包内容的规范化 hash；
- 官方/真实样本反推规则；
- 其他由逆向证据支持的候选。

每个候选记录包 hash、客户端错误、是否出现在列表和是否可启用。不得通过反复随机修改而不留实验记录。

## 9. 平台知识证据等级

| 等级 | 来源 | 可支持的结论 |
|---|---|---|
| E0 | 产品愿望/推测 | 只能登记风险，不能实现为默认事实 |
| E1 | 社区文章/开源旁证 | 可用于 Spike，不能独立升级交付状态 |
| E2 | APK/二进制/真实样本逆向 | 可支持 structural，实现必须标版本 |
| E3 | 官方文档/官方模板 | 可支持 contract，但仍需客户端验证 |
| E4 | 指定客户端/设备真实安装 | 可支持 install_verified（限验证矩阵） |
| E5 | 多版本、多设备定期回归 | 可支持更广泛公开兼容声明 |

每个 provisional 必须记录证据等级和失效日期。客户端大版本升级后，E4 证据需要重新评估。

## 10. 包级通用校验

所有 adapter 必须执行：

- 禁止 `.`、`..`、NUL、空路径和非法绝对路径；
- 平台确需前导反斜杠时由 outlet policy 显式允许；
- 检查重复条目、文件数、单文件和总包大小；
- 资源引用与 ZIP 条目闭合；
- INI/XML/JSON 编码和语法校验；
- 文件名、大小写、扩展名和压缩方式校验；
- 产物 SHA-256；
- 不包含 API Key、原始模型配置或无授权素材；
- 所有 provisional 字段进入 structural report。

## 11. 安装验证 Profile

```ts
interface InstallVerificationProfile {
  outlet: Outlet;
  client: { name: string; version: string; source: string };
  environment: {
    os: string;
    device?: string;
    density?: string;
  };
  installSteps: string[];
  requiredScenarios: string[];
  evidenceExpiresWhen: string[];
}
```

通用 requiredScenarios：

- 客户端识别包；
- 安装/导入成功；
- 出现在皮肤列表；
- 可启用；
- 关键视觉显示；
- 关键状态切换；
- 客户端重启后仍可用；
- 卸载/恢复默认不破坏客户端；
- 失败时错误和日志可定位。

## 12. 状态更新流程

1. 代码任务完成只更新“代码实现”。
2. 单元/合同测试完成可更新 structural report，但不能自动升级本文总览。
3. Browser E2E + outlet profile + 目标资产完成后，提交 Evidence，评审后升级 `previewable`。
4. 完整 AssetProfile + QA + Artifact 完成后升级 `install_candidate`。
5. 真机 Evidence 评审后升级 `install_verified`。
6. 发现回归、客户端升级或证据失效时立即降级，并在 Handoff 记录原因。
