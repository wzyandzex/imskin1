# IMSkin 质量门禁与验收协议

> 版本：v1.0
> 状态：发布约束基线
> 最后更新：2026-08-15
> 关联：`docs/00-总规划与开发基线.md`、ADR-001、ADR-004、ADR-008

## 1. 目的

本文定义一个版本、目标变体和包在什么条件下可以被预览、交给安装测试或向用户称为“可安装”。任何“测试全绿”“文件非空”“逆向结构正确”都不能绕过本文。

质量结论必须是机器可读报告，并引用输入 hash、checker version 和 evidence。没有运行的检查是 `not_run`，不是 passed。

## 2. Gate 总览

```text
G0 需求/确认
→ G1 Schema 与迁移
→ G2 资产完整性
→ G3 渲染后可读性/遮挡
→ G4 平台适配与包结构
→ G5 跨出口一致性
→ G6 浏览器真实交互
→ G7 指定客户端/真机安装
→ G8 性能、安全与人工签收
```

| Gate | 输入 | 输出 | 失败影响 |
|---|---|---|---|
| G0 | Version、Confirmation | 确认报告 | 不允许正式导出 |
| G1 | DesignSnapshot | SchemaReport | 阻断生成/迁移 |
| G2 | AssetBundle、AssetProfile | AssetReport | 阻断 install_candidate |
| G3 | 实际渲染帧 | RenderQAReport | error 阻断 |
| G4 | Adapter project、Artifact | StructuralReport | 阻断该出口 |
| G5 | 四个 TargetVariant | ConsistencyReport | 超阈值阻断相关出口 |
| G6 | Web build、PreviewProfile | BrowserEvidence | 不得标 previewable |
| G7 | Artifact、真实客户端 | InstallEvidence | 不得标 install_verified |
| G8 | RC、环境 | ReleaseReport | 不得公开发布 |

## 3. 状态与 Gate 的映射

| DeliveryLevel | 必须通过 |
|---|---|
| `structural` | G1 + G4 结构子集 |
| `previewable` | G1 + G2 预览子集 + G3 + G6 |
| `install_candidate` | G0 + G1 + G2 全部 + G3 + G4 + G5 |
| `install_verified` | install_candidate + G7；公开 Release 另需 G8 |

状态不能由 UI 本地布尔值直接赋予，必须由报告聚合计算。

## 4. Severity 与放行

```ts
type Severity = "info" | "warning" | "error";
```

- `error`：本 Gate failed，阻断对应状态升级。
- `warning`：允许继续，但必须在用户导出卡片和 Evidence 中展示；用户确认后记录 ack。
- `info`：不要求用户确认，但保留在报告。
- `not_run`：若该检查是当前目标的 required check，等同 failed。

禁止通过把 error 改成 warning 来绕过尚未实现的检查。规则变更必须有 ADR、样本和回归测试。

## 5. G0：用户确认和导出资格

### 5.1 Brief 确认

- DesignBrief 必须展示用户明确字段和推断字段。
- 用户确认或修改后保存 Brief hash。
- Brief hash 改变后，原确认失效。
- CLI 的非交互模式必须显式传 `--accept-brief` 或使用已确认 Brief 文件；默认不能假定同意。

### 5.2 版本定稿

- 只有显式“确认此版本”命令可进入 `confirmed`。
- Confirmation 保存 snapshot SHA-256 和时间。
- 任何 feedback/fork/merge 产生新版本，不能继承 confirmation。
- Web 未确认版本不能下载正式包。
- 开发 CLI 可以 `--experimental` 导出结构包，Artifact 必须 `experimental=true`，文件名和报告明确标注。

## 6. G1：Schema、迁移和不可变性

必须检查：

- schemaVersion 支持；
- 所有 required 字段存在；
- Outlet/状态/颜色/尺寸/路径枚举合法；
- element_id 唯一且可解析；
- targetVariants 与 targetOutlets 对齐；
- 引用的 version/project/asset/artifact 存在；
- snapshot hash 可复算；
- 未知字段符合迁移策略；
- 旧项目迁移报告没有 silent data loss；
- 历史版本不可被外部嵌套引用修改。

最低自动化测试：

- 当前 schema round-trip；
- 每个历史 fixture 的迁移；
- 坏文件/超大文件拒绝；
- fork 后修改子版本不影响父版本；
- unknown enum、循环 parent、失效引用拒绝。

## 7. G2：资产完整性

### 7.1 必需检查

根据 outlet 的 AssetProfile 校验：

- 必需角色存在；
- mediaType、后缀和实际文件类型一致；
- width/height/density/orientation/theme/state 合法；
- byteLength 和 contentHash 一致；
- 九宫格区在图像内且不穿过保护区域；
- 帧序号、总数、时长连续合法；
- 音频格式和时长符合平台能力；
- 所有引用闭合；
- 未使用的孤儿资产列为 warning 或按策略 error；
- 未授权资产阻断公开发布。

AssetProfile 必需资源引用闭合率必须是 100%。

### 7.2 降级规则

- 纯色/渐变设计可作为合法设计资源，但必须符合目标 AssetProfile；如果平台要求位图，不得因为 Web 能渲染 CSS 渐变就视为完整。
- 图像 provider 失败时，若使用确定性替代资源，必须重新走 QA，并在 provenance 标注 fallback。
- 没有替代资源时 TargetVariant 保持 incomplete；不能塞透明 1×1 图片掩盖缺失。

## 8. G3：渲染后质量

### 8.1 可读性

关键普通文字：

- 候选文字；
- 选中候选文字；
- 候选序号；
- 拼音/组合串；
- 按键主字符；
- 功能键文字；
- 状态栏文字/必要图标。

初始硬门槛：对比度 `>= 4.5:1`。若以后区分大字号 3:1，必须明确字体大小/字重和平台渲染条件，不默认降低。

### 8.2 采样方法

- solid：直接计算。
- 简单 gradient：不仅检查两端；在实际文字 bounding box 内至少按 3×3 网格采样，取最差对比度。
- image/nine-slice/复杂背景：用最终 Canvas/DOM 合成结果，在文字 bounding box 内多位置采样。
- 阴影、描边和底板属于实际合成，需在渲染后计算。
- light/dark、orientation、layout、DPI 和 key state 各自独立检查。

当前 image 只给 warning 的实现不能作为 install_candidate Gate。

### 8.3 遮挡与点击区

检查：

- 装饰层不得覆盖候选词、按键或分页按钮的 pointer hit area；
- 标注层在试打模式必须 `pointer-events:none` 或不存在；
- 文本不得溢出/截断到不可读；
- 候选长词、单候选、满页、空候选、翻页态均测；
- 360px 等窄宽不丢失反馈主流程；
- 工具栏和面板不与键盘重叠。

### 8.4 自动修复

- 允许一次确定性自动修复（换文字色、底板、压暗局部背景等）。
- 修复必须产生新版本节点和 diff。
- 修复后重新执行受影响 Gate。
- 第二次仍失败则返回用户可操作错误，不循环重试。

## 9. G4：平台适配与包结构

每个出口独立检查：

- 必需文件和目录；
- 编码、BOM、换行和大小写；
- INI/XML/JSON 语法；
- ZIP 路径、重复条目、CRC、压缩方式；
- 文件数、单文件和总包大小；
- 配置引用与实际条目闭合；
- metadata、GUID、Token、版本字段；
- 资产尺寸和平台命名；
- Artifact SHA-256；
- experimental/provisional 清单。

平台特有规则以 `docs/02-平台能力矩阵与适配契约.md` 为准。

构建器返回 bytes 非空不是通过标准。StructuralReport 必须列出执行过的规则。

## 10. G5：跨出口一致性

### 10.1 硬一致项

- DesignBrief 和设计层 token 来源相同；
- 关键品牌/主视觉、主色、强调色和情绪方向一致；
- element_id 语义一致；
- 用户明确保护元素没有无理由变化；
- 深浅变体的派生关系和反馈同步可追溯。

### 10.2 允许差异

- 平台要求的布局坐标；
- 客户端不支持的能力；
- PC/Android 输入方式和功能栏差异；
- DPI 和方向产生的切图差异；
- 可访问性/可读性修复产生的受控色差。

每个允许差异必须由 capability matrix 或 QA fix 解释，不能仅标“平台差异”。

### 10.3 当前阈值策略

在真实双出口样本未校准前：

- 不使用 RGB 欧氏距离作为唯一发布门槛；
- 使用 token diff + 固定截图 fixture + 人工签收；
- 采集足够样本后评估 CIEDE2000/感知指标并新增 ADR；
- 一致性报告列出 changed token、changed element、允许原因和截图引用。

## 11. G6：真实浏览器交互

jsdom/Vitest 不等于浏览器 E2E。`previewable` 至少需要固定 Chromium 版本完成：

- Idea→追问→Brief 修改/确认；
- 物理键盘和虚拟键盘输入；
- 26 键、T9、候选选择、翻页、退格、空格/回车；
- 中英切换；
- 符号、数字和返回面板；
- 试打模式不被标注层拦截；
- 标注模式正确选中 element_id；
- 平台/设备切换加载不同 PreviewProfile；
- light/dark、DPI 和版本切换；
- feedback→新版本→diff；
- 用户确认→导出门禁；
- 失败、loading、重试和窄屏流程。

还需检查：

- Canvas 不是空白；
- 图片、字体和音频资源成功加载；
- 控制台无未处理异常；
- 关键可访问性：焦点、dialog、tab、aria-live、键盘操作；
- 截图无重叠和截断。

## 12. G7：真实客户端/真机

每个 Artifact 必须绑定 exact SHA-256。验证包括：

1. 指定来源和版本的客户端；
2. 指定 OS/设备/DPI；
3. 按标准步骤安装；
4. 被客户端识别并出现在皮肤列表；
5. 可启用且关键元素正常；
6. 关键输入状态正常；
7. 客户端重启后仍有效；
8. 横竖屏/深浅/DPI 按声明验证；
9. 失败时记录错误、日志和复现步骤；
10. 验证者、时间、artifact hash 和源码版本可追溯。

截图/录屏是证据附件，不是安装行为的替代。

## 13. G8：性能

### 13.1 测试协议

每份性能报告必须记录：

- OS、CPU、内存、设备；
- Node、浏览器和客户端版本；
- 数据集版本；
- 冷/热启动；
- 采样次数；
- P50/P95/P99/max；
- 测试脚本版本。

### 13.2 初始预算

| 指标 | 门槛 | 统计 |
|---|---:|---|
| PC 按键→候选 | <=50ms | 1000 次，P95 |
| T9 按键→候选 | <=50ms | 1000 次，P95 |
| 历史版本切换 | <=1s | 100 次，P95 |
| 音效触发 | <=30ms | 支持测量环境，P95 |
| 动效 | >=50fps | 5 秒序列，掉帧率同时记录 |
| 反馈局部重跑 | 小于同输入全量重跑 | 固定 fixture，P95 |

词库变大后必须重新跑拼音 benchmark，不能沿用种子词库性能结论。

## 14. G8：安全

公开或局域网共享前必须通过：

- 非 loopback 服务强制认证；
- Bearer secret 常量时间比较；
- 不可预测 job/artifact ID；
- 请求体、素材、下载、任务数、并发和 TTL 限制；
- SSRF：协议、主机、私网/metadata、重定向和 DNS 复验；
- 图像 URL 的 MIME、大小和超时；
- ZIP 路径穿越、重复路径和炸弹限制；
- 项目导入 schema/大小/循环引用；
- API Key 不进入项目文件、日志、错误和浏览器默认持久化；
- 用户知道 prompt/素材发送到哪个 provider；
- 依赖审计和 secret scan。

## 15. 发布报告

Release Candidate 至少包含：

```text
release-manifest.json
source-version.txt 或源码包 hash
web-build/
artifacts/<outlet>/...
qa/<report-id>.json
evidence/index.json
compatibility-matrix.md
known-limitations.md
install-guides/
rollback.md
```

`release-manifest.json` 至少记录：

- release ID、时间、构建环境；
- 版本和四出口 deliveryLevel；
- Artifact ID/hash/大小；
- QA report IDs；
- Install evidence IDs；
- 未关闭 warnings/provisional；
- 回滚目标。

## 17. 当前项目的即时判定

基于现有静态审查：

- 四出口最高为 `structural`。
- 平台专属 PreviewProfile 未接入，因此不应标 `previewable`。
- 默认资源/布局不完整，因此不应标 `install_candidate`。
- 没有真机证据，因此没有任何 `install_verified` 出口。
- 现有 305 左右测试是有价值的源码基线，但不能替代 G6/G7/G8。
