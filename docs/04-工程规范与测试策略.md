# IMSkin 工程规范与测试策略

> 版本：v1.0
> 状态：工程约束基线
> 最后更新：2026-08-15
> 关联：`docs/00-总规划与开发基线.md`、`docs/03-质量门禁与验收协议.md`

## 1. 目的

本文规定后续代码的写法边界、包职责、测试分层和统一命令。目标不是形式统一，而是让“代码已实现”和“产品可交付”之间的差距始终可测量。

## 2. 运行环境矩阵

| 项 | 基线 |
|---|---|
| Node | 22.x（CI 固定；24 仅兼容性验证） |
| 包管理 | npm workspaces，锁文件提交 |
| TypeScript | strict；禁止依赖擦除行为差异 |
| 前端 | React 19 + Vite 6 |
| 前端测试 | Vitest（jsdom）+ 固定版本 Chromium E2E（后续） |
| Node 测试 | `node:test` 原生运行器 |
| 浏览器支持 | Chromium 桌面最新两个稳定版；移动 Chrome 作为预览参考 |

禁止假设：

- 开发机 Node 版本等于 CI Node 版本；
- jsdom 等于真实浏览器（无真实 Canvas/音频/权限/DPR）；
- 本地 `npm test` 等于全仓库类型和构建检查（当前根脚本只跑 workspace test）。

## 3. 包边界与依赖方向

```text
contracts（纯类型 + 运行时 parser，零依赖）
  ← pinyin-engine / skin-gen / project-model / feedback-core / qa-core / 四个 adapter
  ← orchestrator
  ← api / web-app
```

规则：

- 依赖只能向下；出现环必须先重构再继续。
- 核心逻辑包保持零第三方运行时依赖；引入依赖需 ADR。
- `web-app`、`api` 不定义领域状态字符串，只消费 `@imskin/contracts`。
- Node-only 模块（如 `node:crypto`）只允许出现在 adapter 的 Node 子路径；浏览器可达代码禁止引入。
- 预览运行时暂留 `web-app`；只有当两个 Android 出口的预览逻辑出现真实共享需求时才抽 `preview-core`（需 ADR）。

## 4. 代码规范

### 4.1 类型与数据

- 公共契约进 `contracts`，带 `schemaVersion` 和运行时 `parse*` 函数；禁止 `as unknown as T` 跨越信任边界。
- 外部输入（LLM、导入文件、API body、素材）一律运行时校验后入库。
- 版本快照不可变：写入深冻结或结构化克隆；禁止共享可变嵌套引用。
- 颜色统一 `#RRGGBB`（或显式 alpha 格式）入库；平台私有编码（BGR 等）只在 adapter 出口转换。
- 时间、随机数、GUID、ID 通过可注入 factory 产生；核心包不得直接调用 `Date.now()/Math.random()`（现有 ProjectStore 的确定性原则保留并推广）。

### 4.2 错误模型

```ts
interface AppError {
  code: string;            // 如 ASSET_MISSING, ADAPTER_BUILD_FAILED
  severity: "info" | "warning" | "error";
  userMessage: string;     // 可直接展示
  technicalMessage?: string; // 不含 secret/用户素材
  retryable: boolean;
  context?: Record<string, string | number | boolean>;
}
```

- 禁止空 `catch {}`；降级必须记录 Diagnostic（stage、原因、是否影响交付等级）。
- 一次操作的三种结局必须可区分：成功 / 成功但降级 / 失败。
- API 错误码稳定且文档化；不得把底层异常原文直接回给用户。

### 4.3 命名与状态

- 领域内只用 `Outlet`（`sogou_pc` 等）和 `DeliveryLevel`；旧字符串只在边界转换层出现。
- 状态值变更属于契约变更，需同步 `contracts`、测试和文档矩阵。
- 注释只写“为什么”和外部事实来源；PROVISIONAL 标记必须同步登记到 `docs/05-风险登记与证据包规范.md`，不允许只留在代码里。

## 5. 测试分层

| 层 | 内容 | 运行 | 何时必须 |
|---|---|---|---|
| L0 静态 | 全仓库 `tsc --noEmit`、lint、格式、import 边界 | 本地 + CI | 每次提交 |
| L1 单元 | 纯函数、状态机、schema、颜色、ZIP 工具 | node:test / Vitest | 每次提交 |
| L2 性质/不变量 | 可读性不变量、版本树无环、快照隔离、局部修改不漂移 | node:test | 每次提交 |
| L3 合同/Golden | 四 adapter 固定输入→固定结构/编码/hash；schema round-trip | node:test | adapter/契约变更 |
| L4 编排/API 集成 | 生成→反馈→fork→QA→导出；job 生命周期；错误码 | node:test | 编排/API 变更 |
| L5 浏览器 E2E | 真实 Chromium 点击/键盘/触摸；Gate G6 场景 | Playwright（后续） | 预览/工作台变更 |
| L6 视觉回归 | 固定 snapshot×outlet×device×theme×DPI 截图 diff | Playwright（后续） | 视觉渲染变更 |
| L7 真机/客户端 | 安装、显示、重启回归；按 evidence manifest | 手动 + 半自动 | 出口状态升级 |
| L8 性能 | 50ms/30ms/1s/50fps 基准 | 脚本化 benchmark | 词库/渲染/预览变更 |
| L9 安全 | 认证、SSRF、路径穿越、大小限制、secret 泄露 | node:test + 扫描 | API/LLM 变更及共享前 |

现有约 305 个测试归入 L1–L4 基线。**L1–L4 通过不构成发布结论**；发布结论只来自 `docs/03` 的 Gate 报告聚合。

### 5.1 必须新增的测试（按缺口）

- 面板切换（symbol/number/返回）与候选/键盘交互回归；
- 试打模式与标注模式的指针事件隔离；
- Brief 确认与定稿门禁（未确认不可正式导出）；
- 反馈提交 loading/异常/重试/防重复 fork；
- DesignSnapshotV1 parser、迁移、坏文件拒绝、深隔离；
- OutletJob 状态机、TTL、取消、重试、四出口互不污染；
- AssetProfile 完整性与引用闭合；
- 分层 QA gate 报告聚合与阻断规则；
- adapter Golden：压缩方式、编码、路径策略、Token/GUID 可注入；
- Chromium E2E 主链路；
- SSRF/认证/大小限制安全测试。

## 6. 统一命令（目标态）

根 `package.json` 补齐（当前只有 `test`）：

```bash
npm run typecheck     # 全仓库 tsc --noEmit（根 tsconfig + references）
npm run lint          # lint（引入 ESLint/Biome 时生效）
npm run build         # web-app vite build（后续含其他构建物）
npm test              # 全部 workspace 测试（L1–L4）
npm run test:e2e      # Chromium E2E（L5/L6）
npm run bench         # 性能基准（L8）
npm run verify        # typecheck + lint + test + build 本地合并入口
npm run ci            # CI 等价命令
```

统一测试统计输出（消除文档数字漂移）：

```bash
npm test -- --reporter spec   # 输出各包用例数；文档不再手写固定数字
```

在此落地前（`ENG-001` 未完成），文档只允许写“以命令输出为准”。

## 7. Git 与变更流程

当前工作区**没有 Git 元数据**——这是最高优先工程风险之一：

- 无法回滚、无法 bisect、无法证明源码版本与产物 hash 对应；
- `GOV-002` 必须包含初始化仓库（首提交即当前基线 + 本批文档）。

初始化后：

- 主干保护；功能分支 + PR；
- Conventional Commits；任务 ID 写入提交说明；
- 每个 PR 通过 L0–L4 才可合并；涉及 Gate 的变更须引用报告；
- 禁止提交：node_modules、dist、.npm-cache、真实用户素材、API Key、未脱敏日志；
- 证据包（截图/录屏）入 `docs/evidence/` 时检查不含敏感信息。

## 8. Definition of Done（工程视角）

一个任务完成必须同时具备：

1. L0 通过（类型/lint/格式）；
2. 对应层测试新增且通过；
3. 错误路径有 code + userMessage + retryable；
4. 降级路径有 Diagnostic 与文案；
5. 契约/状态变更同步 contracts、测试、平台矩阵；
6. 新增 PROVISIONAL 已登记风险台账；
7. 状态升级引用了报告/Evidence ID；
8. 回滚方式明确（Git 后：revert 即回滚）。

## 10. 禁止事项（一票否决）

- 用静态图/录屏冒充可交互预览；
- 用非空 ZIP 冒充可安装包；
- 把 error 降级为 warning 以绕过未实现的检查；
- 在浏览器持久化 API Key 而无用户明确知情；
- 生成“看似成功”的空包掩盖适配失败；
- 未经 Evidence 升级出口交付状态；
- 引入未登记的第三方依赖或 provisional 假设。
