# IMSkin 风险登记与证据包规范

> 版本：v1.0
> 状态：风险管理基线
> 最后更新：2026-08-15
> 关联：`docs/02-平台能力矩阵与适配契约.md`、`docs/03-质量门禁与验收协议.md`

## 1. 目的

本项目最大的风险不是代码 bug，而是**把未验证的外部事实当作已完成能力**。本文把所有“不知道/待验证/未实现”集中成台账，并规定证据包格式，使风险可见、可认领、可关闭、可失效。

## 2. 风险分类

| 类别 | 含义 | 关闭方式 |
|---|---|---|
| `external_fact` | 外部世界的事实未确认（客户端是否接受包、字段语义） | E3/E4 级证据 |
| `capability_gap` | 产品能力未实现（面板、平台预览、资产） | 代码 + 测试 + Gate 报告 |
| `strategy_open` | 实现策略待定（阈值、命名、路由契约） | ADR |
| `engineering_debt` | 工程基础设施缺口（Git、CI、类型门禁） | 任务完成 |

## 3. 风险登记表

每项字段：`ID / 类别 / 描述 / 证据等级 / 影响 / 阻塞的任务或状态 / 验证方法 / fallback / 登记日期 / 状态`。

### R-01 `external_fact` 搜狗 PC 客户端接受性

- 现状：明文 store ZIP + UTF-16LE `skin.ini` 未在真实客户端安装过。
- 影响：`sogou_pc` 无法升级 `install_candidate` 之后任何等级。
- 验证：E4 真机安装（见 §6 清单）。
- Fallback：若拒收，对照官方样本修正容器/编码/字段；加密容器路径已存在可作对照。
- 状态：open。

### R-02 `external_fact` 百度 PC 压缩方式

- 现状：代码用 store ZIP；逆向资料称真实包为 deflate。
- 影响：包可能被客户端拒绝。
- 验证：同资源双包（store vs deflate）对照安装。
- Fallback：切换打包层为 deflate（zip 包能力扩展）。
- 状态：open。

### R-03 `external_fact` 百度 Android Token 语义

- 现状：`Token.txt` 以 Info.txt 字节 MD5 占位。
- 影响：`.bds` 大概率无法导入。
- 验证：Token 候选实验矩阵（见平台矩阵 §8.3）+ 真机。
- Fallback：依据官方样本反推规则；无解则该出口降级 blocked。
- 状态：open。

### R-04 `external_fact` 搜狗 Android 布局键名

- 现状：布局 INI 键名/取值 provisional。
- 验证：真实主题模板样本 + 真机安装。
- 状态：open。

### R-05 `external_fact` 各客户端版本兼容

- 现状：无任何“当前主流版本”固定记录。
- 影响：所有 E4 证据需绑定版本；客户端升级即需复验。
- 验证：兼容矩阵首版（GOV-001 范围）。
- 状态：open。

### R-06 `capability_gap` 平台专属预览

- 现状：PreviewRuntime 无 outlet 参数，平台切换仅影响标签/导出文件名。
- 影响：四出口均不得标 `previewable`。
- 关闭：PRE-001 + MOB-004 + G6 证据。
- 状态：open（任务已定义）。

### R-07 `capability_gap` 符号/数字面板

- 现状：布局/动作已定义但 dispatch 未接通。
- 关闭：UX-001 + 测试。
- 状态：open。

### R-08 `capability_gap` 真实位图资产管线

- 现状：A3 图像生成依赖用户配置 endpoint；默认导出多为配置骨架。
- 影响：所有出口无法 `install_candidate`。
- 关闭：ASSET-001 + AssetProfile 闭合。
- 状态：open。

### R-09 `capability_gap` 词库覆盖

- 现状：种子词库（约 230 词条）仅供开发。**已量化**（2026-08-16，`docs/evidence/pinyin-benchmarks/initial/`）：日常 60 词 top1 仅 8.3%、无候选率 78.3%（qwerty）/43.3%（T9）；引擎自检 98.1% 正确、延迟 p95=0.028ms——**瓶颈在数据不在算法**。
- 附注（排序校准）：SeedDict 以键内书写序位赋权（非真实词频），导致 `xian` 下「西安」被单字列表压制至第 4 位；**词库替换必须携带真实词频数据**（与 R-10 校准族相邻）。
- 关闭：词库选型（含许可审查）+ `Dict` 接口接入 + 本基准复测达标（common top1 ≥0.8、无候选 ≤10%、延迟 p95 ≤50ms）。
- 状态：verifying（基准 harness 已落地；词库替换进行中）。

### R-10 `strategy_open` QA 一致性阈值

- 现状：RGB 欧氏距离为经验值；CIEDE2000 未接。
- 决策：先 token 规则 + fixture + 人工签收；校准后立 ADR。
- 状态：open。

### R-11 `strategy_open` element_id 命名终稿

- 现状：首版命名空间见 `docs/01` §7.1；实现前仍可调整。
- 决策：DOM-001 落地时冻结；此后变更走 schema migration。
- 状态：open。

### R-12 `engineering_debt` 无 Git 仓库

- 影响：不可回滚/追溯；产物无法绑定源码版本。
- 关闭：GOV-002 初始化。
- 状态：open（最高优先）。

### R-13 `engineering_debt` 无统一类型/CI 门禁

- 关闭：ENG-001。
- 状态：open。

### R-14 `security` API 认证与任务生命周期

- 现状：未配 key 默认放行；job 仅内存；ID 可枚举。
- 触发条件：任何非 loopback 部署/共享前必须关闭（SEC-001/JOB-001）。
- 状态：open。

### R-15 `security` 前端 LLM 直连与 Key 存储

- 现状：Key 存 localStorage，浏览器直连任意 Base URL；与文档承诺不一致。
- 关闭：SEC-003（默认不持久化 + 明示直连风险 + 代理优先）。
- 状态：open。

### R-16 `external_fact` 真机能力等价边界

- 现状：振动/音效/动效/DPI 在浏览器内为模拟或未实现。
- 规则：UI 必须明示“模拟/降级”；不得假装等价（SRS C-5）。
- 状态：open（随 MOB-002/003 收口）。

## 5. 证据包目录规范

```text
docs/evidence/
  README.md                     # 索引与规则（本文件姐妹篇）
  outlets/
    sogou-pc/<client-version>/
      manifest.json             # 必需，见 §6
      artifacts/                # 包 + sha256
      screenshots/
      logs/
      notes.md
    sogou-android/...
    baidu-pc/...
    baidu-android/...
  pinyin-benchmarks/<dataset-version>/
  visual-golden/<fixture-id>/
  performance/<date>-<env>/
  security/<date>-<scope>/
```

命名小写连字符；一次验证一个目录；禁止覆盖历史目录——复验就开新目录并互链。

## 6. 出口安装证据 manifest.json（必需字段）

```json
{
  "evidenceId": "ev_...",
  "outlet": "sogou_pc",
  "deliveryLevelClaim": "install_verified",
  "source": {
    "commit": "<git sha>",
    "treeHash": "<源码树 hash>",
    "buildProfileVersion": "..."
  },
  "artifact": {
    "artifactId": "art_...",
    "fileName": "...",
    "byteLength": 0,
    "sha256": "..."
  },
  "client": { "name": "...", "version": "...", "source": "official" },
  "environment": { "os": "...", "device": null, "density": null },
  "installSteps": ["..."],
  "scenarios": [
    { "id": "recognized", "result": "pass", "note": "", "screenshot": "screenshots/01.png" }
  ],
  "requiredScenarios": ["recognized","installed","listed","enabled","visuals","states","restart"],
  "failures": [],
  "verifier": { "name": "...", "date": "2026-08-15" },
  "knownLimitations": [],
  "linkedEvidence": []
}
```

硬规则：

- `artifact.sha256` 必须与被安装文件完全一致；
- 任一 requiredScenario 非 pass → 不得声明 `install_verified`；
- 失败实验也归档（failures 数组），失败是事实证据；
- 敏感信息（账号、序列号、未授权素材）不得入包。

```json
  "engineVersion": "...",
  "samples": 10000,
  "top1HitRate": 0.0,
  "top3HitRate": 0.0,
  "noCandidateRate": 0.0,
  "t9Top1HitRate": 0.0,
  "latency": { "p50ms": 0, "p95ms": 0, "p99ms": 0 },
  "environment": { "node": "22.x", "cpu": "..." },

```

## 8. 风险状态流转

```text
open → verifying（实验/任务进行中）→ closed（证据归档）
                ↘ mitigated（fallback 已生效，根因保留）
closed → reopened（客户端升级/回归/证据失效）
```

- 关闭风险必须在平台矩阵同步状态升级；
- reopened 必须立即降级对应出口 deliveryLevel；
- 每次周会/阶段评审先过一遍 open 清单。

## 9. 当前“绝对不要做”清单

- 不要基于 E1 级（社区/开源旁证）资料升级任何交付状态；
- 不要在无 Git 前做大范围重构（不可回滚）；
- 不要把失败实验的包发给用户；
- 不要为了关闭风险修改 manifest 事后凑数——证据生成时间与内容必须真实。
