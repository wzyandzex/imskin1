# ADR-002 设计层与厂商×设备目标变体

- 状态：已接受（2026-08-15）
- 关联：`docs/01` §4/§9、`docs/02` §3

## 背景

当前 `exportSkinSet` 把同一份 SkinManifest 和同一组 images 分发给四个 adapter，平台差异只剩文件名与配置映射；架构文档要求的“设计层 + 四象限适配层”未落地。

## 备选方案

1. 继续单一 manifest + 四映射器——简单但平台反馈无处安放，资产无法按出口独立重跑。
2. 每出口完全独立设计——丢失“同一设计”一致性，反馈需改四份。
3. 设计层共享 + 每版本四个 `TargetVariant`（资产集/能力/预览/QA/产物独立）。

## 决策

方案 3。`DesignSnapshot` 持有平台无关 brief/spec/elements + `Record<Outlet, TargetVariant>`；通用风格反馈同步设计层后四端重适配；平台反馈只改对应 TargetVariant。

## 后果

- 正面：平台隔离、象限重跑、“四端同一设计”可被 diff 证明。
- 负面：快照体积与状态复杂度上升；需要 contracts 与迁移配合。

## 迁移

现有 SkinManifest 成为设计层渲染契约的兼容视图；`exportSkinSet(images)` 逐版本废弃，改由各 TargetVariant 的 assetSet 驱动。

## 回退

若四变体维护成本过高，可先只在移动/PC 各保一个代表变体，但 Outlet enum 与状态模型不变。
