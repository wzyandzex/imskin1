# ADR-005 LLM 密钥与自定义 endpoint 安全边界

- 状态：已接受（2026-08-15）
- 关联：`docs/04` §10、R-15

## 背景

现状：前端把用户 API Key 存 localStorage 并在浏览器直连任意 Base URL；`docs/LLM与自动化API.md` 却声称“前端不直连、经后端代理”——文档与实现矛盾，存在 Key 泄露与 SSRF 面。

## 备选方案

1. 维持现状——不可接受（共享设备/XSS/导出泄露）。
2. 仅前端加密存储——伪安全，密钥仍在客户端。
3. 分层：默认“仅本次会话”不持久化 Key；直连模式显式风险告知；本地 API 代理为推荐路径；服务端对 baseUrl/图片 URL 做协议/主机/重定向/大小校验。

## 决策

方案 3。短期（SEC-003）：默认不持久化、UI 明示“浏览器直连，Key 仅存本机内存”；项目导出永远不含模型配置。中期：LLM 调用走本地 API 代理（`api` 包扩展 `/v1/llm/*`），Key 存进程环境变量；代理实施 SSRF 防护（禁私网/metadata、限 HTTPS、复验重定向、限制下载大小与超时）。

## 后果

- 正面：Key 暴露面收敛；与文档承诺一致；服务端部署有网络边界。
- 负面：代理路径增加部署复杂度；纯静态托管时只能用直连模式（需显式确认）。

## 迁移

SettingsPage 增加“会话级密钥”默认值与风险文案；`modelConfigs` 持久化时剥离 apiKey 字段（存量 localStorage 数据一次性清除明文 Key）。

## 回退

若本地代理不可用，可保留直连模式，但必须维持默认不持久化与风险告知，不得恢复 localStorage 明文。
