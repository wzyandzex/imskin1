# ADR-006 本地任务生命周期与四出口进度

- 状态：已接受（2026-08-15）
- 关联：`docs/01` §10、`docs/06` JOB-001

## 背景

当前 API 的 job 是内存 Map + 自增 ID + 简单 0→0.6→1 进度；无取消/重试/TTL/并发上限；四出口共用一个任务状态，“快的出口先体验”无从谈起。

## 备选方案

1. 直接引入持久化队列（BullMQ/Redis）——依赖与部署成本超前，当前无多租户需求。
2. 保持现状——任务不可靠且进度失真。
3. 本地受控任务模型：每出口一个 OutletJob（stage/progress/attempt/TTL/cancel/retry），进程内实现但语义完整，接口可替换为持久化实现。

## 决策

方案 3。job 状态机：`not_started→queued→generating_assets→adapting→qa→packaging→succeeded/failed/cancelled`；UI 展示 stage 而非伪造平滑百分比；并发上限与任务数上限可配置；ID 不可预测。

## 后果

- 正面：分出口进度/失败/重试真实可见；未来接队列只换实现。
- 负面：进程重启仍丢任务（如实标注“本地模式”，不做假持久化承诺）。

## 迁移

`AutomationService.generateSync` 改为按 outlet 派生 OutletJob；REST `/v1/generations/:id` 响应增加 `outlets` 进度明细。

## 回退

无（现状即被否决）；若队列需求到来，以适配器替换实现，不改状态机语义。
